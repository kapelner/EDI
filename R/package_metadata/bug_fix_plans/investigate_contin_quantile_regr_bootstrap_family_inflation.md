## The finding

`InferenceContinQuantileRegr` shows CONSISTENT-direction (unlike TODO-19's
mixed-direction pattern) severe Type-I error inflation across multiple
bootstrap-family p-value methods:
- `compute_rand_bootstrap_two_sided_pval`: 0.185 vs. nominal 0.05.
- studentized variant: ~0.285 vs. nominal 0.05.
- plain `compute_rand_two_sided_pval` (permutation, not bootstrap): 0.061,
  near nominal — looks fine.

The fine/broken split tracks exactly along the permutation-vs-bootstrap
boundary: the problem is specific to the bootstrap-family resampling path,
not this class's estimator generally.

## Hypothesis 1 (original) — REFUTED 2026-09-23 by direct code trace, high confidence

**Claim**: `private$fit_warm_keep`, a private field caching warm-start state
outside `cached_values` (`inference_continuous_quantile_regr.R:176`,
`:215-231`), is a stale-cache bug of the same class as TODO-12's
`cached_mod` finding — reused stale fit state across bootstrap draws would
plausibly bias results in a consistent direction.

**Refuted**: the `private$fit_warm_keep` warm-start reuse path
(`inference_continuous_quantile_regr.R:218-225`) only activates when
`reuse_factorizations = TRUE` (`get_ci_fit_controls()`, `:208-214`, reads
`private$randomization_mc_control$fit_reuse_factorizations`). Exhaustively
traced every site that sets `randomization_mc_control` across
`R/EDI/R/*.R`: it defaults to `NULL` (`inference_all_abstract_rand.R:350`)
and is populated **only** inside CI-search/bisection
(`inference_all_abstract_rand_ci.R:279-280`, `:403`), restored via
`on.exit` afterward. A standalone `compute_rand_bootstrap_two_sided_pval()`
call — the flagged method, not a CI computation — never touches this code
path, so the `fit_warm_keep` branch never executes for the flagged methods.
Not a stale-cache bug.

## Hypothesis 2 (current, medium confidence, code-reading only, NOT yet reproduced) — BRT tie-manufacturing

BRT (bootstrap-resampling-of-treatment / randomization-bootstrap) draws are
generated by `bootstrap_sample_indices()`
(`inference_all_abstract_rand_bootstrap.R:662`) — confirmed a
**with-replacement** row-index draw (duplicating rows), not a permutation
(which reshuffles treatment labels on the same n distinct rows, never
duplicating).

`quantreg::rq()`'s simplex ("br") method and its Powell-style sandwich SE
are both known in the quantile-regression literature to be numerically
sensitive to exact row/response ties — a with-replacement bootstrap
manufactures ties directly (duplicated rows are, by construction, exact
ties). This would explain the exact fine/broken split observed
(permutation fine, every bootstrap-family variant broken) without any code
defect — possibly a genuine statistical instability, not a bug.

**Important caveat, stated up front**: this may turn out not to be a
"fixable" code defect at all. The eventual writeup might be "document BRT
isn't recommended for quantile-regression classes" or "add a tie-breaking
jitter before refitting," not a simple correction. Don't assume a fix is
possible before the reproduction step below.

## Next steps (none done yet — do these before attempting any fix)

**Static re-audit 2026-10-09:** confirmed the proposed experiment must use
`generate_rand_bootstrap_draws()`: every BRT draw calls the actual
`bootstrap_sample_indices(private$n, bootstrap_type)` path and carries the
resulting `i_b` into its materialized design assignment. This preserves the
with-replacement duplication mechanism under investigation; it is not a
hand-built permutation substitute. The required quantitative fixture and
negative controls cannot be run on this host because `Rscript` fails before
loading EDI (`libmkl_gf_lp64.so.2` is unavailable). No causal conclusion or
mitigation has therefore been claimed.

**Installed-package pilot 2026-10-14:** after the user's reinstall, an
exploratory 25-replicate null run on `DesignSeqOneByOneKK14` (`n=60`, one
continuous covariate, `model_formula = ~1`, `B=r=99`) did not reproduce the
historical inflation: quantile plain-randomization rejected 1/25, quantile
BRT percentile 0/25, and quantile BRT studentized 0/25. The OLS negative
control rejected 2/25 for each BRT variant. A separate 12-draw pilot using
`generate_rand_bootstrap_draws()` produced 16--26 duplicated rows per draw;
the resulting quantile fits had finite estimates and SEs, but no tie-count /
fit-instability correlation was established. These are limited pilot results,
not the comprehensive-test DGP, so TODOs remain open and no fix or dismissal
of the historical finding is warranted. The installed library reports EDI
1.0.3.

**Matched-draw tie-sensitivity extension 2026-10-14:** ran 50 independent
sharp-null cases on installed EDI 1.0.3, each with `n=60`, one continuous
assignment covariate, `model_formula = ~1`, and rounded continuous outcomes
`round(0.5*x + error, 1)`. For each case, generated one batch of 12 actual
BRT draws through `generate_rand_bootstrap_draws(B=12, materialize_w=TRUE)`
from the Quantile inference object, then passed that exact batch into
`compute_brt_null_statistics_with_se()` for Quantile, OLS, and RobustRegr.
Thus the comparison denominator is 600 identical draw/model pairs per
estimator, not 1,800 independently generated resamples. All 600/600 estimates
and all 600/600 SEs per estimator were finite, with positive SEs. The draws
contained a median 22 duplicated rows (range 11--32 of 60) and median 72
within-resample tied-response pairs (range 36--173).

Within-case Spearman correlation medians for duplicate-row count versus
`log(SE)` were -0.055 (Quantile), -0.021 (OLS), and -0.080 (RobustRegr);
versus absolute studentized draw statistic they were 0.027, 0.053, and 0.074.
Quantile's median absolute studentized statistic was 0.450, versus 0.625 for
OLS and 0.609 for RobustRegr; its per-case median was lower than OLS in 1st-
to-3rd quartile paired differences (median -0.111), and lower than RobustRegr
(median -0.122). This bounded fixture shows no Quantile-specific increase in
fit failures, SE collapse, or tie-count association relative to the controls;
it does not establish the cause of the historical comprehensive-suite result
or refute sensitivity on its DGP. With only 12 draws per case the empirical
two-sided p-value floor would be 2/12, so these are draw-level fit/tie
diagnostics, not a Type-I-error test. Unique artifacts:
`/tmp/edi-v105-todo20/tie_sensitivity_probe.R`,
`/tmp/edi-v105-todo20/same_draws.csv`,
`/tmp/edi-v105-todo20/within_case_correlations.csv`, and
`/tmp/edi-v105-todo20/summary.csv`. No build/install or workspace CSV write
was performed. TODO-20 remains open; no mitigation is supported by this
evidence.
