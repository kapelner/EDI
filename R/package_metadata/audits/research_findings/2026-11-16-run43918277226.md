### glmm-marginal-likelihood: gauss-hermite-quadrature, louis-identity → Collapse to cluster totals (log link). Per group g: S_g=Σw_i y_i, log Λ_g=log Σw_i e^{η_i} (via LSE), A_g=Σw_i(y_iη_i−log y_i!). Node log term = log w_k + A_g + b_k S_g − exp(b_k + log Λ_g), which is O(G·K). Gradient: β-part = Xᵀ[w⊙(y − e^{η}⊙E_g[e^b])], one GEMV. The σ-part comes from per-group posterior moments E_g[b(S_g−Λ_g e^b)]. Louis Hessian: β-β = −Xᵀdiag(w e^η E_g[e^b])X, one weighted crossprod. Cross and E[GGᵀ] terms come from u_g=X_gᵀwy, v_g=X_gᵀwe^η and E_g[e^b], E_g[e^{2b}], E_g[b e^b], E_g[b² ...]. This is the same quadrature-approximated likelihood algebraically; only the summation order changes. The cluster-total sufficiency is the Hausman–Hall–Griliches structure, and the per-group integral is a Poisson-lognormal-type 1-D function of (S_g, Λ_g, σ). EDI's hurdle kernel already uses the multiplicative e^{η}·e^{b_k} sharing.
- **Current:** Fixed 60-node non-adaptive GH. Each objective call evaluates exp(η_i+b_k) and the per-row log term over all n rows at every node (m_mu_all_k_mat, n×60 exp calls), then one X'·(n-vector) GEMV per node for the β gradient. The Hessian does 60 weighted_crossprod calls (O(n·K·p²)) plus per-group per-node X_gᵀ products. Cost is O(n·K·p) per evaluation and O(n·K·p²) per Hessian.
- **Claimed speedup:** Not quantified by any source. This is my derivation from the code. The n-dependent work drops from O(n·K·p) to O(n·p) per evaluation, with O(G·K) left for the quadrature, so up to about K=60× on the dominant term when n ≫ G. In KK designs (pairs plus singletons, G≈n/2–n) the remaining G·K exp/LSE work is about half to all of the current n·K exp count. A realistic per-evaluation gain is then the removed K·p GEMV/crossprod work plus about 1–2× fewer exps, perhaps 3–10× on gradient+Hessian for p≈5–20. Must be measured. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: medium)
- **Trade-offs:** Identical estimator and deterministic. Results change only at the floating-point rounding level (summation order), so the existing lme4/glmmTMB equivalence tests should pass unchanged, but bitwise identity with the old kernel is lost. Overflow guards must move to log space: use exp(b_k + log Λ_g) with log Λ_g computed by LSE, instead of the current min(700) clamp per row. This also makes the 60-node default (raised after the R8 grid) almost free, which weakens the speed case for AGQ on the Poisson kernel; AGQ stays an accuracy item. Does not apply to logistic, clogit or ordinal kernels (no multiplicative separation). The hurdle kernel cannot fully collapse because of the per-row truncation term log(1−e^{−λ}).
- **Suggested action:** Add a catalog §4 Adopt item for fast_poisson_glmm.cpp: rewrite PoissonGLMMObjective::operator() and hessian (and the score/Hessian exports at :515,:545) in cluster-total form. Gate on existing Poisson GLMM tests plus an all.equal (tol 1e-10) A/B against the current kernel on the R8 grid, then benchmark at n=100–1000. Cite the hurdle kernel's multiplicative exp sharing as precedent.
- **Affects:** `R/EDI/src/fast_poisson_glmm.cpp::PoissonGLMMObjective`, `R/EDI/src/fast_poisson_glmm.cpp::hessian`, `R/EDI/src/fast_poisson_glmm.cpp::fast_poisson_glmm_internal`, `R/EDI/R/inference_count_KK_combined.R::shared_rcpp`, `R/EDI/R/inference_count_KK_combined.R::compute_estimate_with_bootstrap_weights`, `R/EDI/R/inference_count_KK_combined.R::compute_treatment_estimate_during_randomization_inference`
- **Sources:** https://en.wikipedia.org/wiki/Fixed-effect_Poisson_model https://cran.r-project.org/package=poilog

### glmm-marginal-likelihood: gauss-hermite-quadrature, lbfgs → Adaptive GH with fewer nodes, by either of two routes. (a) Exact AQ gradient by implicit differentiation of the per-group mode, reusing the inner Cholesky, with L-BFGS (Stringer, arXiv 2310.01589v2, still a preprint with no journal DOI). (b) Pseudo-adaptive GHQ: centre and scale nodes once per group from an initial fit and keep them fixed, so the existing cheap fixed-node analytic gradient applies (Rizopoulos 2012, CSDA 56(3):491–501, doi 10.1016/j.csda.2011.09.007).
- **Current:** Fixed non-adaptive GH (20 nodes logistic/clogit/engine, 7 nodes hurdle) with the exact fixed-node gradient, optimized by L-BFGS (LBFGSpp).
- **Claimed speedup:** Stringer: about 2–4× faster than lme4/GLMMadaptive at m=1000, n=5 (relative to other packages, not to EDI). Rizopoulos: 'considerably faster than the standard Gauss–Hermite rule', not quantified on the abstract page; a later application cited in search results reports 6 pseudo-adaptive nodes ≈ 20 standard. Against EDI's 20 fixed nodes at m_g≤2 the gain is not quantified and probably small; catalog T1 estimates 1.2–1.6×. (applies at EDI's sizes: unknown; keeps the estimator: no; confidence: low)
- **Trade-offs:** Changes results at quadrature tolerance, so it is an approximation change, not a drop-in. The main benefit is accuracy at large σ. Pseudo-adaptive nodes fixed from a pilot fit are less accurate if the pilot is far from the MLE (e.g. across randomization/bootstrap replicates). Deterministic. The Stringer code license is unstated; reimplement rather than copy.
- **Suggested action:** Keep under v1.1.0 performance_profiling_and_upgrades.md TODO-153. Add the Rizopoulos 2012 DOI as the frozen-mode route next to Stringer 2024. Lower priority for the Poisson kernel if the cluster-total rewrite lands (the 60 nodes become cheap); prioritise the logistic/clogit 20-node kernels and the hurdle K=7 accuracy item.
- **Affects:** `R/EDI/src/fast_logistic_glmm.cpp::value`, `R/EDI/src/fast_logistic_glmm.cpp::LogisticGLMMObjective`, `R/EDI/src/fast_logistic_glmm.cpp::fast_logistic_glmm_internal`, `R/EDI/src/fast_clogit_plus_glmm.cpp::neg_glmm`, `R/EDI/src/fast_clogit_plus_glmm.cpp::fast_clogit_plus_glmm_cpp`, `R/EDI/src/fast_clogit_plus_glmm.cpp::fast_clogit_plus_glmm_internal`, `R/EDI/src/_glmm_engine.h::GLMMObjective`, `R/EDI/src/_glmm_engine.h::value`, `R/EDI/src/fast_hurdle_poisson_glmm.cpp::HurdlePoissonGLMMObjective`, `R/EDI/src/fast_hurdle_poisson_glmm.cpp::fast_hurdle_poisson_glmm_internal`, `R/EDI/R/inference_incidence_KK_cond_logit_glmm_abstract.R::shared`, `R/EDI/R/inference_proportion_KK_combined.R::InferencePropKKGLMM`
- **Sources:** https://arxiv.org/abs/2310.01589 https://arxiv.org/html/2310.01589v2 https://ideas.repec.org/a/eee/csdana/v56y2012i3p491-501.html
