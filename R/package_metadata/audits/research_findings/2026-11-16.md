## 1. Faster-algorithm findings
### Batch A.1: bootstrap refits (L-BFGS, zero start) → Warm-start every draw at the observed-sample MLE (shifted by the hypothesized δ where applicable). Run Newton with the analytic Weibull Hessian already in the file (the newton_then_lbfgs path) to full convergence, with L-BFGS as fallback.
- **Current:** Per draw: L-BFGS from an all-zero (β, log σ) start, maxit 100, tol 1e-8, OpenMP over B.
- **Claimed speedup:** Not quantified for Weibull. Davidson & MacKinnon (nonlinear.pdf, abstract and §2): starting from the original estimate, a 'fixed, small number of Newton or quasi-Newton steps' suffices, and fewer for Newton than quasi-Newton, because Newton converges quadratically from a √n-consistent start. The catalog's own estimate is ~2× fewer iterations from the warm start. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: medium)
- **Trade-offs:** Same MLE only if each draw iterates to the full tolerance. A fixed k-step version (as in Davidson–MacKinnon) is an estimator change and must not be adopted silently. (β, log σ) is not jointly concave, so a different start could change which rare fits fail, and an A/B on the failure set is needed. Deterministic: the start depends only on the observed fit, not on the thread.
- **Suggested action:** Keep the Prototype verdict (TODO-3). Prototype a warm start plus Newton to convergence and compare the BRT draws and the failure set against the current zero-start L-BFGS.
- **Affects:** `R/EDI/src/fast_weibull_regression.cpp::compute_weibull_rand_bootstrap_parallel_cpp`
- **Sources:** https://russell-davidson.research.mcgill.ca/articles/nonlinear.pdf

### Batch A.1: BFGS (MASS::polr) → Extend the existing C++ weighted cumulative-link Newton kernel (fast_ordinal_regression_weighted_cpp, logit only today) to probit and cloglog. Use the regularized Newton with step-halving and analytic gradient and Hessian, in the original (non-reparametrized) cutpoint parametrization, as ordinal::clm does.
- **Current:** MASS::polr (optim BFGS on exp-increment reparametrized cutpoints) per Bayesian-bootstrap draw, for probit, cauchit and the logistic surrogates (adjacent-category, stereotype, KK cond adj-cat).
- **Claimed speedup:** Not quantified. The clm article (§3) says NR with analytic derivatives is 'virtually instant' on concave CLM likelihoods, and that the original parametrization is 'generally closer to quadratic … which facilitates faster convergence' than polr's exp-increment reparametrization. (applies at EDI's sizes: unknown; keeps the estimator: yes; confidence: low)
- **Trade-offs:** Same MLE for logit, probit and cloglog: their likelihood is concave (Pratt 1981, Burridge 1981, cited in the article). Cauchit is nonconcave, so keep polr or add a safeguarded path for it. The logistic surrogate calls for adjacent-category and stereotype fit a cumulative-logit model, which is a different model from the class's own; that is an estimand question, not a speed one. The results are not bit-identical to polr, so tolerance tests are needed.
- **Suggested action:** Re-look under the existing 'Investigate': benchmark the C++ weighted Newton kernel against polr per draw at EDI n for probit, and add the weights argument to the probit and cloglog kernels if it wins.
- **Affects:** `R/EDI/R/globals.R::weighted_ordinal_bootstrap_surrogate_fit`
- **Sources:** https://mirror.linux.duke.edu/pub/cran/web/packages/ordinal/vignettes/clm_article.pdf

### Batch A.1: alternating IRLS / Newton (glm.nb) → fastglm::fastglm_nb: a C++ NB2 MLE with the same alternation, a moment-initialized θ, step halving, weights and offset.
- **Current:** MASS::glm.nb (R-level alternating IRLS for β and theta.ml Newton for θ), fallback path only.
- **Claimed speedup:** Not quantified for NB (the vignettes report convergence, not timing). Convergence: 200/200 vs MASS 165/200 at n=200, p=9, θ=1. Log-likelihoods agree within 1.5e-06 and θ within 4.3e-07 when both converge. (applies at EDI's sizes: unknown; keeps the estimator: yes; confidence: low)
- **Trade-offs:** Adds a dependency for a fallback-only path. The license was not verified this run. The main gain is robustness, not speed.
- **Suggested action:** Low priority. If the KK21 fallback's glm.nb failures matter, consider fastglm_nb or EDI's own C++ NB kernel, after checking the license.
- **Affects:** `R/EDI/R/helper_robust_regression.R::robust_negbinreg`
- **Sources:** https://mirror.dogado.de/cran/web/packages/fastglm/vignettes/nb-convergence-fastglm.html https://archive.linux.duke.edu/cran/web/packages/fastglm/vignettes/nb-stability-fastglm.html https://rdrr.io/cran/fastglm/man/fastglm_nb.html
