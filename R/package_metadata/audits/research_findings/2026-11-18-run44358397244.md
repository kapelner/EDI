### clmm-ordinal-mixed-fit: multistart → Before fitting, run the single linear-programming overlap test of Sablica, Hornik & Rusch (2026) to decide whether a finite MLE of the cumulative-link fixed part exists. When it does not, skip the multistart and polish and mark the fit or replicate non-estimable directly, consistent with EDI's separation warnings. `clmm-ordinal-mixed-fit#44358397244.3`
- **Current:** On (quasi-)separated ordinal data or Bayesian-bootstrap replicates, all 5 log σ starts run L-BFGS toward a divergent β, followed by an L-BFGS polish and up to 50 FD-Hessian Newton steps. Non-existence is only detectable afterwards from huge estimates or SEs; v1.0.6-TODO-76 added that kind of post-hoc check for the ordinal GEE class.
- **Claimed speedup:** Not quantified. On separated inputs it saves the whole multistart plus polish (≈5+ L-BFGS runs and up to 50·2d gradients) for one small LP. On non-separated inputs it adds one LP. (applies at EDI's sizes: unknown; keeps the estimator: yes; confidence: low)
- **Trade-offs:** This is mainly a robustness item: it gives a principled non-existence flag in place of heuristics on the fitted estimate. The paper's criterion is for the fixed-effects categorical model, and whether it carries over exactly to the random-intercept marginal likelihood is unverified (a random intercept does not usually restore existence when fixed-effect separation exists, but this needs checking). No code release was found, and an LP solver dependency would need a GPL-compatible license.
- **Suggested action:** Investigate, at low priority: read the paper's LP formulation and check on a separated KK ordinal dataset whether it flags the cases where the CLMM/GLMM fits diverge. If it does, consider it as a shared pre-check alongside the v1.0.6-TODO-76 separation handling.
- **Affects:** `R/EDI/src/fast_ordinal_glmm.cpp::fast_ordinal_glmm_internal`, `R/EDI/src/fast_ordinal_clmm.cpp::run_fast_ordinal_clmm`
- **Sources:** https://arxiv.org/abs/2610.08100 https://doi.org/10.48550/arXiv.2610.08100

### cox-ph-fit: newton-raphson → After accepting a step-1 candidate with |ll - ll_candidate| < tol, stop with converged = TRUE. When estimate_only and no caller needs the Hessian at the final beta, skip the confirming pass. Otherwise, run only the cheap gradient pass for gradient_norm. A Newton-decrement test (g'H⁻¹g/2 < tol, available from the LDLT already computed) also lets the loop stop before evaluating the candidate. The returned beta is bit-identical under the first variant, because the same candidate is accepted. `cox-ph-fit#44358397244.1`
- **Current:** Each Newton iteration computes the full ll, gradient and Hessian (compute_cox_ll_grad_hess_fast, O(np²) per stratum sweep). The next iteration recomputes all three at the accepted candidate, only to find |old_ll - ll| < tol and stop. The candidate's ll was already computed by compute_cox_neg_ll_only (O(np)) in the step-halving check. So every converged fit pays one extra full grad+Hessian pass, about 1 of the 3-8 iterations, and more in relative terms for warm-started randomization and bootstrap replicates that converge in 2-3 iterations.
- **Claimed speedup:** Not quantified for EDI. lifelines' changelog (0.15.0) says its Newton-decrement criterion "typically shaves off a single step, resulting in generally faster convergence". For EDI that means saving 1 of k O(np²) passes per estimate-only replicate, roughly 15-40% of the kernel time depending on k, before the R-call overhead. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: low)
- **Trade-offs:** With estimate_only, the C++ wrapper also returns fisher_information, gradient_norm and min_eigenvalue_information at the final beta. Usability checks (e.g. rcpp_cox_fit_is_usable) and warm_start_fisher_info may consume them. Skipping the pass makes these values come from the previous iterate, or requires a gradient-only pass. Check every consumer first. The Newton-decrement variant changes beta within tolerance, so it is not bit-identical; the |Δℓ|-candidate variant is. The Lin-Wei, SE and vcov paths (estimate_only = FALSE) still need the final Hessian and gain nothing.
- **Suggested action:** Count iterations (num_iter) on a KK and stratified Cox randomization run. If most replicates converge in ≤4 iterations, prototype the early stop for estimate_only = TRUE behind a check that fisher_information and gradient_norm are not consumed, and compare beta bit-for-bit on the package_tests CSVs.
- **Affects:** `R/EDI/src/fast_coxph_regression.cpp::cox_newton_raphson`, `R/EDI/R/inference_survival_coxph.R::generate_mod`, `R/EDI/R/inference_survival_strat_cox.R::generate_mod`, `R/EDI/R/inference_survival_KK_strat_cox.R::shared`
- **Sources:** https://lifelines.readthedocs.io/en/stable/Changelog.html https://pypi.org/project/lifelines/ https://cran.r-project.org/web/packages/FastSurvival/readme/README.html

### kk21-covariate-weights: alternating-irls-theta → Use MASS::theta.ml's update θ ← θ + score/info. This is the same info expression, with the opposite sign of the step. Optionally step on log θ or add step-halving, as fastglm_nb does, so θ stays positive without clamping. Fix the R reference in test-kk21-negbin-fast-digamma.R, which copies the wrong sign, and test against MASS::glm.nb / theta.ml. `kk21-covariate-weights#44358397244.1`
- **Current:** The θ step is θ_new = θ − score/info (kk21_weights.cpp:570 and :1045), clamped to [0.01, 1000]. Here info = Σ[−ψ'(y+θ) + ψ'(θ) − 1/θ + 2/(θ+μ) − (y+θ)/(θ+μ)²], which is the positive observed information (minus d score/dθ). The step therefore moves away from the root. θ drifts to the 0.01 or 1000 clamp, where Δθ = 0 meets the tol test and ends the loop. The weights w = μ/(1+μ/θ) and the Wald SE then use a boundary θ, not the NB2 MLE.
- **Claimed speedup:** Not quantified; this is mainly a correctness fix. As a side effect, the outer loop should converge in a few Newton steps at the MLE instead of walking to a clamp. Not measured. (applies at EDI's sizes: yes; keeps the estimator: no; confidence: high)
- **Trade-offs:** This is a correctness/robustness finding, not a pure speedup. The fix changes the output (KK21 NB weights become the intended NB2 Wald |t|), so existing fixtures and the test reference change. It is reached only when count_use_speedup = FALSE (the default is TRUE), in both the KK21 and the KK21stepwise count paths. The fix is deterministic and needs no new dependency. MASS is GPL-2 | GPL-3 and is only a reference.
- **Suggested action:** Flip the sign at kk21_weights.cpp:570 and :1045, and in the test's R reference. Add a test that θ̂ matches MASS::theta.ml(y, fitted(glm.nb)) on a fixture, and that θ̂ is not at a clamp. Then rerun the KK21 count weight comparisons.
- **Affects:** `R/EDI/src/kk21_weights.cpp::univariate_negbin_tstat`, `R/EDI/src/kk21_weights.cpp::multivariate_negbin_tstat`, `R/EDI/src/kk21_weights.cpp::kk21_negbin_weights_cpp`, `R/EDI/src/kk21_weights.cpp::kk21_stepwise_negbin_weights_cpp`
- **Sources:** https://raw.githubusercontent.com/cran/MASS/master/R/negbin.R https://cran.r-project.org/package=MASS https://cran.r-project.org/web/packages/fastglm/vignettes/nb-convergence-fastglm.html

### likelihood-tests-null-refits: multistart → A profiled null refit. With beta_T = delta moved into an offset, profile beta (GLS) and sigma_e^2 (closed form) out and search a single bounded parameter lambda = sigma_b^2/sigma_e^2 in [0, lambda_max] with Brent or a safeguarded 1-D Newton. This is the lme4 / MixedModels.jl profiled-deviance construction, with theta >= 0 handled exactly at the boundary. KK groups come in only two sizes (pairs and singletons), so the GLS weight c_g = v_b/a_g takes only two values. The normal equations are therefore A_pairs - c2(lambda) B_pairs + (1 - c1(lambda)) A_single-type sums, built once in O(n p^2), and each profile evaluation costs O(p^3), independent of n. The existing fast_gaussian_lmm_gls_cpp is the building block. One deterministic 1-D search replaces both L-BFGS starts and the 1e-4 switching rule. `likelihood-tests-null-refits#44358397244.1`
- **Current:** The KK GLMM fit_null(delta, start) runs fast_gaussian_lmm_cpp: joint L-BFGS over (beta, log sigma_e, log sigma_b) with beta_T fixed (maxit 300, eps_g 1e-6). When a warm start is passed (every CI-inversion step after the first), it runs a second full refit from the full-fit parameters and keeps it if its NLL is lower by more than 1e-4. The reason is that log sigma_b near the sigma_b = 0 boundary has a vanishing gradient and L-BFGS stops at a non-optimum. Cost: up to 2 x iters x O(n p) per delta.
- **Claimed speedup:** Not quantified by the sources. By construction it removes the second start (2x fewer refits during CI inversion) and replaces up to 300 O(n p) L-BFGS iterations with about 20-40 O(p^3) profile evaluations after one O(n p^2) pass. The catalog (row NEW-lmm-closed-form) judged the full-fit version 'speed roughly neutral at p <~ 10'. The gain here comes mainly from dropping the second start and the boundary crawl. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: medium)
- **Trade-offs:** Same ML estimator (not REML), with an exact boundary optimum at sigma_b = 0 where the current code can stop early, so p(delta) may differ slightly from the current output near the boundary (it should be better, not worse). It is deterministic and removes the p(delta) jitter that the 1e-4 margin works around (lrt_ci_nr_cpp tol_p = 1e-7). Risk: the 1-D profile can in principle have more than one local maximum, so bracket it with a coarse lambda grid (cheap, at O(p^3) per point) before Brent. It needs the A/B harness. It extends the catalog's existing 'Prototype' option (profiled 1-D Brent, v1.0.5 algorithm-choice-audit TODO-3) to the constrained null refit, where the two-start workaround (v1.0.6-TODO-115) now doubles the cost. It also improves robustness, not only speed.
- **Suggested action:** Prototype a profiled constrained refit for fast_gaussian_lmm (offset delta*w, lambda grid plus Brent on [0, lambda_max], GLS via the existing fast_gaussian_lmm_gls_cpp normal equations precomputed per group size). Use it in the KK GLMM fit_null in place of the two-start L-BFGS, then A/B the LR, score and gradient p-values and CIs against the current output on the KK fixtures, including boundary (sigma_b ~ 0) cases.
- **Affects:** `R/EDI/R/inference_continuous_KK_glmm.R::run_fit`
- **Sources:** https://www.jstatsoft.org/v67/i01/ https://arxiv.org/abs/1406.5823 https://juliastats.org/MixedModels.jl/stable/optimization/

### likelihood-tests-null-refits: analytic-derivatives → Once the cross blocks are zero, the efficient information for beta_T (a Schur complement over all other parameters) equals the Schur complement within the beta block alone, sum_g X_g' P_g X_g. A score-test-only path can compute just that p x p block, reuse the sorted LMMData, and compute it once per fit rather than once per accessor. `likelihood-tests-null-refits#44358397244.3`
- **Current:** block_diag_information(fit) calls get_gaussian_lmm_fisher_cpp, which rebuilds LMMData (sort and regroup, O(n log n)) and computes the full (p+2)x(p+2) analytic observed Hessian, including the variance-parameter block and the cross blocks. The cross blocks are then set to zero. It is called separately for score, observed_information, fisher_information and information at each delta.
- **Claimed speedup:** Not quantified. Constant factor: it skips the variance-block and cross-block O(n) terms and repeated O(n log n) regrouping per delta. Small at p <~ 10. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: low)
- **Trade-offs:** Identical score statistic (an algebraic identity once the blocks are zero). There is also a documentation mismatch: the code comment says 'expected information', but the variance block is the observed Hessian. That block does not affect the score test, but it does affect anything else that reads `information` (for example a full-vector vcov). Low priority.
- **Suggested action:** Low priority. Fold this into the profiled-refit prototype: return a cached beta-block information from the null fit and fix the comment ('observed Hessian with cross blocks zeroed; beta block equals expected').
- **Affects:** `R/EDI/R/inference_continuous_KK_glmm.R::block_diag_information`
- **Sources:** https://juliastats.org/MixedModels.jl/stable/optimization/
