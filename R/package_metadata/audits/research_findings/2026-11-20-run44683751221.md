## 1. Faster-algorithm findings (new; each needs a triage decision)
### survival-frailty-copula-mle: analytic-derivatives → (1) Exact and cheap: in the FD Hessian, difference only the free coordinates (fixed_spec.free_idx). Central-difference column i depends only on perturbing parameter i, and the symmetrized free block uses only free rows and columns, so the inverted block and the SE are bit-identical. The frailty replicate cost drops from 2(p+2) to 2p gradient evaluations, and Clayton from p+3 to p+1. (2) Larger: a closed-form observed information for the GH frailty likelihood. It is the posterior-weighted complete-data Hessian minus the posterior score covariance (Louis identity), per Pan & Thompson 2003, who give the closed-form score and observed information for GH-approximated GLMMs. With the cluster-total collapse of finding #43925959437.1, this is O(np^2 + GK) and costs about one gradient pass. If LAGHQ (#43925959437.2) is adopted, Charvat 2023 gives the closed-form Hessian directly. Same estimator and same beta; SEs, and hence the IVW pooled estimate, change only at FD-error level (more accurate). `survival-frailty-copula-mle#44683751221.1`
- **Current:** Since v1.0.6-TODO-86 (commit 5bdb9dfb, 2026-11-19), every IVWC resampling or randomization replicate calls fast_weibull_frailty_cpp / fast_clayton_weibull_aft_optim_cpp with estimate_only = FALSE to get the draw's own variance. That runs obj.hessian(par) every replicate. The frailty fit uses central FD over all p+2 parameters, 2(p+2) gradient evaluations at O(nKp) each. Clayton uses forward FD, p+3 evaluations. This happens even when fixed_idx pins the two variance-component parameters and only the free p-by-p block is inverted (fast_weibull_frailty.cpp:398-408).
- **Claimed speedup:** Not quantified by any source. Theoretical: at p=2, option (1) cuts the frailty Hessian from 8 to 4 gradient evaluations and Clayton from 5 to 3. Option (2) cuts the frailty Hessian to about 1-2 gradient-equivalents. Against a warm-started L-BFGS replicate of an estimated 20-40 evaluations, that is roughly 10-25% of per-replicate time for the frailty IVWC classes (my estimate, unmeasured). (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: medium)
- **Trade-offs:** (1) has no numerical change and no new dependency. (2) means deriving and testing an analytic Hessian; the catalog notes the dep-cens analytic Hessian was disabled as dead code (I-3), so it needs a check against central FD to about 1e-6 relative. Deterministic in both cases. It does not matter for estimate-only classes that skip vcov.
- **Suggested action:** Reopen catalog NEW-fd-hessian (its Keep reason no longer holds after v1.0.6-TODO-86). First restrict FD to free_idx in WeibullFrailtyNormalLikelihood::hessian, ClaytonWeibullLikelihood::hessian and DepCensTransformLikelihood::hessian, and test that the SE is bit-identical. Then fold an analytic GH information into v1.2.0-TODO-22 alongside the cluster-total collapse, and benchmark per-replicate time for the frailty IVWC randomization test at n=50-500 pairs.
- **Affects:** `R/EDI/src/fast_weibull_frailty.cpp::WeibullFrailtyNormalLikelihood`, `R/EDI/src/fast_survival_models_optim.cpp::ClaytonWeibullLikelihood`, `R/EDI/R/inference_survival_GLMM_weibull_frailty_normal.R::frailty_for_matched_pairs`, `R/EDI/R/inference_survival_GLMM_weibull_frailty_loggamma.R::clayton_copula_for_matched_pairs`

### weibull-aft-mle: lbfgs → On the standardized scale, run the existing damped Newton (newton_then_lbfgs) from the smart cold start and drop the L-BFGS phase plus separate polish; keep L-BFGS only as Newton's existing fallback. The standardization now removes the conditioning problem that was the main risk of Newton-first. Apply the same in the BRT kernel, with the smart or observed-MLE start that the catalog already lists. This is new code-level evidence for the catalog's Prototype v1.0.5 TODO-3, not a new idea. `weibull-aft-mle#44683751221.1`
- **Current:** Since 2026-11-18 (v1.0.6-TODO-112), when columns are badly scaled, fit_weibull_aft_with_column_scaling runs the default L-BFGS on the standardized design and then up to 5 full Newton polish steps with the analytic Hessian, because L-BFGS stops with coefficients about 1e-3 off. On well-scaled data the fit is L-BFGS alone. compute_weibull_rand_bootstrap_parallel_cpp still runs L-BFGS from all-zero params with no polish.
- **Claimed speedup:** Not quantified by a source. The catalog's own estimate is L-BFGS 15-40 iterations versus Newton 4-8. The current path adds up to 5 Newton steps on top of L-BFGS. arXiv 2310.01589 reports, in another model, that Newton iterations from an L-BFGS endpoint are usually needed only once, which supports Newton converging quickly near the optimum. Expected gain is modest (perhaps 1.2-2x per fit at p <= 10), multiplied in bootstrap and randomization loops. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: low)
- **Trade-offs:** Same MLE, since the optimum is unique for the Weibull AFT; only the iteration path changes, so rare failing fits may differ and an A/B on convergence failures is required, as TODO-3 already says. Accuracy improves: the code documents L-BFGS ending about 1e-3 off in coefficients, and the BRT kernel has no polish, so randomization replicates may carry that error. That part is a robustness/accuracy point, not speed. Deterministic, with no thread or seed dependence.
- **Suggested action:** Attach to the existing v1.0.5 TODO-3 prototype. Benchmark the standardized-scale newton_then_lbfgs path against lbfgs+polish (iterations, wall time, failure rate) on survival::colon and the simulation DGPs, including compute_weibull_rand_bootstrap_parallel_cpp with a smart start.
- **Affects:** `R/EDI/src/fast_weibull_regression.cpp::fast_weibull_regression_internal`, `R/EDI/src/fast_weibull_regression.cpp::fast_weibull_regression_left_interval_censoring_internal`, `R/EDI/src/fast_weibull_regression.cpp::fast_weibull_regression_cpp`
- **Sources:** https://arxiv.org/html/2310.01589 https://doi.org/10.48550/arXiv.2310.01589 https://cran.r-project.org/web/packages/survival/news.html
