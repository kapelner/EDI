## 1. Faster-algorithm findings
### cox-ph-fit: breslow-risk-set-cumsum → Sort once by (stratum, time, dead desc), then take within-stratum reverse cumsums of exp(eta - max eta). This gives one risk sum per failure time (Breslow) for both the NLL and the cumulative hazard. The NLL is already implemented in C++ as compute_cox_neg_ll_only.
- **Current:** .cox_neg_loglik_breslow_r is live: kk_cox_fully_fixed_null_fit calls it, including once per parametric-bootstrap draw. It uses a per-stratum which() plus a per-event risk-set rescan, O(n·S + nD), about O(n²) for KK pairs. .breslow_hazard rescans `y_o >= t_k` for each event time, O(nK).
- **Claimed speedup:** Not quantified by any source. The complexity drops from O(n²) or O(nK) to O(n log n), or O(n) once sorted. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: medium)
- **Trade-offs:** Tolerance-equal (summation order changes); the max-eta shift also improves overflow robustness. Deterministic. Needs fixtures with ties and strata, plus a check that the inventory row 'dead code' label is corrected.
- **Suggested action:** Carried over from the previous run unchanged; the code is unchanged. Implement the Adopt verdict for .breslow_hazard (v1.0.5 audit TODO-7). Route kk_cox_fully_fixed_null_fit to the C++ reverse-cumsum NLL and verify it agrees to 1e-10.
- **Affects:** `R/EDI/R/inference_survival_coxph.R::.cox_neg_loglik_breslow_r`, `R/EDI/R/helper_survival_fits.R::.breslow_hazard`
- **Sources:** https://cran.r-project.org/web/packages/glmnet/vignettes/coxdev.html https://arxiv.org/abs/2310.16238 https://doi.org/10.48550/arXiv.2310.16238

### cox-ph-fit: newton-raphson → Build the rungs lazily, yielding the next rung only after the previous fit is rejected. The order is the same and the same design is accepted, so the result is bit-identical.

- **Claimed speedup:** Not quantified. It saves up to about 12 × O(np²) per call, multiplied by the number of randomization or bootstrap replicates. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: low)
- **Trade-offs:** Implementation change only, with no numerical change. Profile first.
- **Suggested action:** Carried over from the previous run unchanged. Profile shared() on a KK strat-Cox randomization run, and make the ladder lazy if the cost is material.

### balanced-allocation-optimization: simulated-annealing, branch-and-bound-milp → Special-case p = 1 (one covariate) for the mahal_dist, D (P from [1,x] with fixed n_T) and l1 kinds. Each objective is then a monotone function of |Σ_T x̃ − Σ_C x̃|, i.e. the balanced number partitioning problem (Kallus 2018 eq. 2.8 shows the reduction and its NP-hardness). Use the balanced largest differencing method (BLDM, O(n log n)) as the start and Mertens' complete-Karmarkar-Karp extension (BLDM+CKK) to search to a certified optimum, an anytime algorithm that returns BLDM first. Equal-cardinality |m| ≤ 1 is exactly Mertens' 'balanced' case. Kapelner's own GreedyExperimentalDesign already ships a Karp method for one covariate.
- **Current:** For any p, n ≤ 20 uses the GLPK Fortet MILP (l1 uses MILP at any n), and n > 20 uses 4-chain single-swap SA with 20k moves (no optimality certificate).
- **Claimed speedup:** Not quantified for EDI. Mertens (arXiv cs/9903011) reports BLDM at O(n log n) time and O(n) space. CKK node counts peak near n_c ≈ 30 for 25-bit integers and fall beyond it. For ≤ 12 significant digits the exact search is 'arbitrary size in practice' (a claim adopted from Korf). With double-precision covariates the hard region extends to larger n, so certification may be exponential near n ≈ 50–60, but BLDM alone should already beat SA's discrepancy. No source compares it with SA or MILP on this problem. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: medium)
- **Trade-offs:** Applies only when p = 1 (after centering), and not to the A-ratio or custom kinds. When CKK runs to completion it returns the exact optimum (the same estimator as MILP, and better than SA's best-found). If it is time-capped it is an anytime heuristic, and its quality relative to SA must be checked. Deterministic, with no RNG. Floating-point covariates need either exact differencing in double or scaling to integers, and the scaling would change near-tie choices.
- **Suggested action:** Prototype. Add a p = 1 branch in optimal_solve_auto that calls a C++ BLDM+CKK kernel with a node/time cap. Check against enumeration at n ≤ 24 and against SA at n = 50/100/200 (objective and wall time). Record it as a new row in catalog §12 table (a)/(b).
- **Affects:** `R/EDI/src/design_optimal_annealing_search.cpp::annealing_design_search_cpp`, `R/EDI/R/helper_optimal_annealing.R::annealing_solve_kernel`, `R/EDI/R/helper_optimal_milp_solvers.R::milp_solve_quadratic`, `R/EDI/R/helper_optimal_milp_solvers.R::milp_solve_l1`, `R/EDI/R/helper_optimal_annealing.R::optimal_solve_auto`
- **Sources:** https://arxiv.org/abs/cs/9903011 https://ar5iv.labs.arxiv.org/html/cs/9903011 https://doi.org/10.1111/rssb.12240 https://academic.oup.com/jrsssb/article/80/1/85/7048414 https://arxiv.org/pdf/1312.0531 https://cran.r-project.org/package=GreedyExperimentalDesign
- **Open copies** (publisher page blocks automated access): https://arxiv.org/abs/1312.0531 https://arxiv.org/abs/1312.0531.pdf

### balanced-allocation-optimization: branch-and-bound-milp → Low-rank convex MIQCP solved by open-source SCIP via the CRAN package scip (1.10.1-1, published 2026-10-04, Apache-2.0; SCIP 10.0 is Apache-2.0): minimize θ subject to θ ≥ ||z||², z = Mw (p continuous variables), Σw = n_T, w binary, through scip_add_quadratic_cons. This removes all n²/2 auxiliary variables with no commercial dependency. Also usable through CVXR ≥ 1.8.2.
- **Current:** Fortet/McCormick product linearization with n(n−1)/2 continuous y_ij and 3 rows per pair, solved by GLPK. The catalog rejected the low-rank MIQP formulation because 'MIQP needs a commercial solver (not GLPK)'.
- **Claimed speedup:** Not quantified. The SCIP 10 report (arXiv 2511.18580) says it is faster than SCIP 9, with larger gains on nonlinear problems, but has no MIQP or balanced-allocation breakdown. The catalog itself predicted that 'MIQP solvers handle this well'. (applies at EDI's sizes: unknown; keeps the estimator: yes; confidence: low)
- **Trade-offs:** This overturns the catalog's licensing objection, which predates the scip CRAN release reviewed here, but not its bound-quality concern: the continuous relaxation of ||Mw||² is ≈ 0 at w = n_T/n, so B&B may still blow up near n ≈ 25. At n ≤ 30, enumeration (v1.0.5-TODO-1) is likely still faster. The ratio kind needs a Dinkelbach outer loop around the MIQCP. Building scip from source needs CMake and C++17.
- **Suggested action:** Re-look. Add 'scip' as an optional backend for the low-rank formulation behind requireNamespace. Benchmark it against GLPK Fortet at n = 15/20/25/30 (p = 5) and against the enumeration prototype. Update catalog §12 table (a), low-rank row, to record that an Apache-2.0 MIQCP solver is available.
- **Affects:** `R/EDI/R/helper_optimal_milp_solvers.R::milp_solve_quadratic`, `R/EDI/R/helper_optimal_milp_solvers.R::milp_solve_A_dinkelbach`, `R/EDI/R/helper_optimal_milp_solvers.R::prepare_optimal_objective_matrices`
- **Sources:** https://cran.r-project.org/package=scip https://cran.r-project.org/web/packages/scip/readme/README.html https://bnaras.github.io/scip/articles/scip-examples.html https://arxiv.org/abs/2511.18580
