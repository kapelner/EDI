### atkinson-optimal-biased-coin: atkinson-da-biased-coin → Use the imbalance-vector form, as covadap::DABCD writes Atkinson's rule: P depends only on a = z_t' C_t^-1 v_b, where C_t = Z'Z over the previous subjects (w-independent) and v_b = sum over treated z_i (running, O(p) update). Precompute g_t = C_t^-1 z_t once per t; it is w-independent and can be zero-padded to the full column set. Then a = v_b'g_t costs O(p) per (b,t), and pi = (a-1)^2/((a-1)^2+a^2), equal to EDI's (M11/A+1)^2/(...) since M11/A = -1/a. Track the invertibility quantity s = n_T - v'C^-1v (the RSS of w on Z) with the recursive-residual recursion s_t = s_{t-1} + (w_{t-1} - a_{t-1})^2/(1+h_{t-1}), where h = z'C^-1z is precomputed. That is O(1) per step and reuses a. Recompute s directly only at the t where indep_cols changes. With this, step_data shrinks to the g_t and h_t vectors, O(np). `atkinson-optimal-biased-coin#44618445718.1`
- **Current:** Per replicate b and per t, the code rebuilds the (t-1)x(p+2) design [w,1,X], forms X'X in O(tp^2), and runs FullPivLU plus a full inverse in O(p^3), using one row. It also stores O(n^2 p) X_prev copies. The adopted plan (v1.0.5-TODO-5/TODO-3) moves to the Schur form with C_t^-1 stored per t: O(p^2) per (b,t) and O(np^2) memory.
- **Claimed speedup:** Not quantified by any source. My own flop count: the draw loop drops from B·n·p^2 (adopted Schur plan) to B·n·p, about p-fold (~10× at p = 10). With the adopted plan's once-per-t precompute included, n = 200, p = 10, B = 501 goes from ~1.2e7 to ~3e6 flops (~4×), or ~400× against the current LU kernel. Memory goes from O(n^2 p) (current) or O(np^2) (plan) to O(np). (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: medium)
- **Trade-offs:** Same probability up to roundoff, so it is not bit-identical. A coin flip changes only when a uniform falls within ~1e-12 of p. RNG consumption is unchanged, so streams stay aligned and determinism across threads and seeds is kept. The FullPivLU 'not invertible -> 0.5' branch has to be reproduced through an explicit tolerance on s and on C_t's conditioning, and the recursive RSS can accumulate roundoff over t, so s should be recomputed exactly at column-set changes and perhaps periodically. a == 0 maps to the existing A == 0 -> 0.5 branch. This is a refinement of the already-adopted Schur rewrite, not a competing design, so it costs little to fold into the same TODO.
- **Suggested action:** When implementing v1.0.5-TODO-5/TODO-3, store g_t = C_t^-1 z_t (and h_t) per t rather than C_t^-1, compute a = v'g_t in O(p), and track s via recursive residuals. Before switching, cross-check probabilities against the current LU kernel and against covadap::DABCD on random designs, including binary covariates where s can hit 0.

### bootstrap-confidence-interval: double-bootstrap → Nankervis-style deterministic inner stopping. Draw the inner replicates for outer b in small chunks, in draw-index order with per-draw seeds. After each chunk, bound the final rank of est among the inner draws: c_below ≤ final count below ≤ c_below + remaining, and the final finite n lies between the current finite count and that count plus the remaining draws. Stop once the covered indicator is the same for every reachable final configuration, at every grid α still being scored. Because this only skips draws that cannot change covered[b], α_adj and the CI are bit-identical to the full computation for a given seed. It composes with the earlier hoist finding #43925959437.1: one stored outer×inner set scored at all 5 α. The stopping rule then needs to resolve all 5 indicators, so it stops at the most demanding α. Draws that would make est outside the CI at α/4 still need nearly the full 51. `bootstrap-confidence-interval#44618445718.1`
- **Current:** For each outer resample b, EDI computes all n_inner = 51 inner refits, keeps the finite ones, forms the type-8 percentile inner CI at grid α, and records only covered[b] = (est inside the CI) (lines 2372-2381). This is done separately for each of the 5 grid α values, about 26.8k refits at defaults.
- **Claimed speedup:** Not quantified for CIs by a fetched source. The arXiv 2404.05006 Remark 2.10 says Nankervis's rules avoid second-level computation that does not affect the resulting interval. A search snippet (not fetched) reports up to a 15× cut in replications for double-bootstrap tests. Arithmetic on EDI's code, not a source claim: for the roughly 85-95% of outer resamples where est is central, the indicator at α up to 2α = 0.1 with 51 draws is settled after about 3-5 draws on each side of est, about 8-15 inner draws. Non-covered outer resamples need all 51. That gives about 2.5-3.5× fewer inner refits, on top of the hoist's ≈4.6× (≈5.8k → ≈2.0-2.5k refits incl. the final B = 501). ### monte-carlo-test-inversion-ci: bisection, brent-root → An exact breakpoint sweep for minlike exact p-values. Both components are exponential families in δ: d+ ~ Bin(k, expit δ), and the reservoir n11 ~ noncentral hypergeometric with log-OR δ. So log f(x;δ) − log f(x_obs;δ) = (log c_x − log c_obs) + (x − x_obs)·δ is affine in δ. The set of support points summed in each minlike p therefore changes only at the closed-form points δ_x = (log c_obs − log c_x)/(x − x_obs), shifted by the log1p(1e-7) tie tolerance EDI uses. There are at most k + S such points. This is the structure the exactci vignette uses for the Poisson minlike CI, and Klaschka & Reiczigel (2021) give fast algorithms at these discontinuity points. Between consecutive points of the merged, sorted list, each component's p is a smooth sum of pmfs over a fixed index set, and the δ-free log c_x are precomputed once. Evaluating the combined p at each breakpoint and its one-sided limits gives three things exactly: (a) whether the acceptance set is empty, which replaces the optimize and 2001-grid fallback; (b) the outermost accepted pieces, i.e. Fay's matching interval, the smallest interval containing all non-rejected δ; (c) each endpoint, from one bracketed root solve inside a single smooth piece, where Brent or ITP is superlinear. `monte-carlo-test-inversion-ci#44618445718.1`
- **Current:** The Zhang exact combined CI works in four steps. (1) The inside point comes from 3 candidates, then stats::optimize, then, since 2026-11-19 (v1.0.6-TODO-157), a 2001-point grid plus 5 local optimize refinements. (2) Doubling to an outside point. (3) Up to 100 bisection steps to width 1e-6 on each side. (4) Every evaluation recomputes binom_two_sided_pval (O(k) dbinom) and fisher_noncentral_two_sided_pval (about 3S lgamma calls plus O(S) exp). Bisection from the inside point returns the crossing nearest to it. When the minlike p is non-unimodal, that can be an inner crossing rather than the outermost accepted δ.
- **Claimed speedup:** Not quantified by any source; derived from the code. On the empty-set or hard path, about 2001 + 5×~25 evaluations, each with about 3S lgamma calls, become about (k+S) breakpoint evaluations with no lgamma. That is roughly 5–20× at k, S of a few hundred. On the normal path (3 candidates + about 2×(doubling + 20–40 bisection steps)) the cost is similar or modestly lower; the gain there is exact endpoints and no missed outer crossing, not speed. Absolute times are milliseconds either way. (applies at EDI's sizes: yes; keeps the estimator: unknown; confidence: medium)
- **Trade-offs:** This is mainly a robustness and correctness finding; it is a speed finding only for the new grid fallback. Where the acceptance set is an interval, the result equals the current one within tolerance. Where the set is non-convex (minlike p's can be non-unimodal; Fay 2010; Klaschka & Reiczigel 2021), the sweep returns the matching interval, which can be wider than what bisection from the inside point now returns. That is an interval change, and arguably a fix. The breakpoints must mirror EDI's 1e-7 relative tie tolerance exactly, or the p at a breakpoint differs. The combined Fisher/Stouffer/min_p p within a smooth piece need not be monotone, so the in-piece root solve must check its bracket. It is deterministic and needs no new dependency: a port into zhang_exact_speedups.cpp. exactci and exact2x2 (GPL-3) are single-component references to test against. The catalog's 'Exact-discrete CI inversion' table already lists 'enumerate jump points' as an option, not rejected, marked as needed only if exact endpoints are wanted. What is new is that the 2026-11-19 grid fallback (v1.0.6-TODO-157) now pays a dense scan to work around exactly the non-unimodality the sweep handles exactly.
- **Suggested action:** Re-open the catalog row 'enumerate jump points' (Exact-discrete CI inversion table) in light of v1.0.6-TODO-157. Prototype a δ-free precompute plus a merged-breakpoint sweep for the combined minlike p, replacing zhang_ci_inside_point_grid and the inside-point bisection. Check it against the current output on fixtures where the set is an interval, and against exact2x2/exactci on single-component cases (m=0; reservoir empty). Record whether the CI should be the matching interval when the set is non-convex.
- **Affects:** `R/EDI/R/inference_helpers_zhang.R::zhang_ci_inside_point`, `R/EDI/R/inference_helpers_zhang.R::zhang_bisect_ci_boundary`, `R/EDI/R/inference_helpers_zhang.R::zhang_ci_exact_combined`, `R/EDI/R/inference_helpers_zhang.R::zhang_compute_ci_bounds_parallel`

### quantile-rank-regression: barrodale-roberts-simplex, interior-point-lp → Closed-form special case for covariate-free designs (the reduced X is [1, w]). β0 is the τ-quantile of the control y (or logit y), as an order statistic (inverse ECDF, not type-7 interpolation). β_T is the τ-quantile of the treated y minus β0. For BB replicates, use weighted group τ-quantiles, which are unique almost surely under continuous Dirichlet weights. Computed by O(n) selection in C++ or R. Fall back to the LP when the solution is non-unique (τ·n_g is an integer for either group, or ties at the cut), unless br's vertex choice is first reproduced and tested. `quantile-rank-regression#44618445718.1`
- **Current:** Every fit, including each randomization draw (rq.fit br, or fn for the proportion class) and each BB replicate (formula rq() with weights, br), solves the full LP through quantreg, even when the reduced design is just [intercept, w].
- **Claimed speedup:** Not quantified by any source. The cost drops from an LP solve plus R/quantreg call overhead to one O(n) selection per group. Per-draw randomization and BB loops would gain most. Unmeasured. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: low)
- **Trade-offs:** This is exact only when the LP solution is unique. With τ=0.5 and even group sizes (common under balanced complete randomization) the solution set is an interval: br returns one vertex and fn a near-centroid point, so a fallback is required there and the win shrinks. A tutorial check found a mismatch at τ=0.25 between sample-quantile differences and rq output (non-uniqueness or quantile type), which confirms that the order-statistic definition and the uniqueness test must be exact. ### rerandomization-sampling: rejection-sampling → Small-n exact sampler. When C(n, n_T) is small (n ≤ ~20-24), walk every n_T-subset in revolving-door Gray-code order, where consecutive subsets differ by one swap (Knuth TAOCP 4A §7.2.1.3; Mütze survey §4.1). Maintain d = M·s incrementally in O(p) per step (one row of M out, one in), and record the subsets with f ≤ cutoff. This builds the acceptable set A exactly. Then draw r indices i.i.d. uniformly from A, with replacement, using the draw-indexed seeds. This is exactly the law of i.i.d. rejection sampling: uniform on A, independent draws. Dispatch when C(n, n_T)·p < (r/p_acc_est)·(n + np); p_acc can be estimated from a pilot or from the chi-square approximation. At prob_T = 0.5 the mirror halves the walk, because membership in A is symmetric. Reuse the DesignFixedOptimal enumeration kernel already proposed in catalog §12 table (a) (new TODO candidate 1: revolving door + O(p) incremental objective + OpenMP by prefix). `rerandomization-sampling#44618445718.1`
- **Current:** Cutoff path: i.i.d. acceptance-rejection. Each candidate is a full Fisher-Yates shuffle plus an O(np) balance check, so the expected cost is r/p_acc candidates × O(n + np). The run is capped at max(1000r, 1e5) candidates and errors if fewer than r are accepted.
- **Claimed speedup:** Not quantified by a source. My arithmetic, not a measurement: n=20, p=5, r=1000, p_acc=1e-3 needs ~1e6 candidates × ~120 flops ≈ 1.2e8 by rejection, against C(20,10) = 1.85e5 × O(p) ≈ 1e6 by enumeration, about 100x. At larger p_acc, or n ≥ ~28, rejection wins, hence the dispatch rule. fastrerandomize offers exact enumeration (generate_randomizations_exact) and recommends Monte Carlo above about 20 units, which supports the crossover. (applies at EDI's sizes: yes; keeps the estimator: yes; confidence: medium)
- **Trade-offs:** Same design law and deterministic for any thread count (the enumeration order is fixed, and accepted indices are sorted before sampling). It changes the RNG stream, so seed-pinned draws for small n change once. An incremental d drifts in floating point, so recompute d from scratch for candidates within a tolerance of the cutoff, or periodically, so that accept/reject matches the direct formula. It also has robustness gains: |A| is known exactly, so the 'could not find r acceptable allocations' error becomes exact (A empty) instead of budget-limited, and the realized acceptance probability |A|/C(n,n_T) can be reported. Memory is O(|A|) indices. This applies to the cutoff path only, not to prop_acceptable, whose 'best r of N draws' law would change.
- **Suggested action:** Add a row to catalog §P6: 'exact enumeration of A (revolving-door Gray code, O(p) incremental), then r i.i.d. draws from A, for small C(n, n_T)'. If v1.0.5's DesignFixedOptimal enumeration kernel (catalog §12 new TODO candidate 1) is built, expose a 'collect all subsets with f ≤ a' mode and dispatch DesignFixedRerandomization's cutoff path to it. Benchmark at n = 12-24, p = 2-10, p_acc = 1e-1 to 1e-4.
- **Affects:** `R/EDI/src/rerandomization_helpers.cpp::rerandomization_search_cpp`, `R/EDI/R/design_fixed_rerandomization.R::generate_rerandomized_w_batch`, `R/EDI/R/design_fixed_rerandomization.R::generate_one_rerandomized_w`
- **Sources:** https://cran.r-project.org/web/packages/fastrerandomize/refman/fastrerandomize.html https://cran.r-project.org/web/packages/fastrerandomize/news/news.html https://arxiv.org/html/2202.01280v4 https://doc-gitlab.sagemath.org/html/en/reference/combinat/sage/combinat/gray_codes.html https://journal.r-project.org/articles/RJ-2019-027

### robust-m-regression: irls → Huber–Dutter 'H-algorithm' / deweighting MM step. Huber ρ″ ≤ 1 (and bisquare ψ′ ≤ 1), so the quadratic majorizer with unit curvature gives β ← β + (XᵀX)⁻¹Xᵀ σ̂ψ(r/σ̂).
