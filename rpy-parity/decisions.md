# Settled decisions

Findings the owner rejected, and conventions. The audit agents read this file and must not raise a finding that matches one below. The owner may edit it by hand.

- `python/cpp/bindings_binary.cpp::fast_logistic_regression`: The docstring says the IRLS fit declares "convergence when either the score norm or the step norm falls below tol". In the kernel, only the score norm decides the returned `converged` flag. After a step-norm exit the gradient is recomputed and `converged = (last_grad_norm < tol)`, so the step norm only stops the loop. (rejected in PR #40; id 92dad1cad19a)
- `python/cpp/bindings_ordinal.cpp::fast_ordinal_glmm`: Python docstring: "warm_start_beta : Optional starting values for coefficients." R roxygen: "Optional starting values either for the full parameter vector (same length as warm_start_params above) or for beta alone (length p, with cutpoints zeroed and log_sigma = -3)". The kernel accepts length p or the full length. The Python text omits that the full-vector form is accepted and what the other entries are set to. (rejected in PR #40; id f6c72567b774)
- `python/cpp/bindings_proportion.cpp::fast_beta_regression`: Docstring says "Returned 'b' is [beta, log_phi] (phi optimized on the log scale for positivity)". The kernel sets res.b = params.head(p) (beta only) and returns phi on its natural scale as 'dispersion' (res.dispersion = exp(params[p])). The R roxygen says coefficients is length p and phi is on its natural scale. (rejected in PR #40; id 3026a66ffbf1)
- `python/cpp/bindings_survival.cpp::fast_weibull_frailty`: The docstring says max_abs_log_sigma is the "Maximum allowed value for log(sigma) (the frailty SD)." The kernel clamps both log_sigma_eps and log_sigma_u (the shape and frailty log-scales) to the symmetric range [-max_abs_log_sigma, +max_abs_log_sigma]. The main description in the same docstring does say both are clamped to +/- max_abs_log_sigma. (rejected in PR #40; id 4b8fd644ea33)
- `python/cpp/bindings_count.cpp::fast_poisson_regression`: The parameter list says "warm_start_weights : Optional initial IRLS working weights for the first iteration." In the kernel, warm_start_weights is only length-checked (`require_length(warm_start_weights, n, "warm_start_weights")`) and is never used in the IRLS or optimizer paths. (rejected in PR #43; id fd5c55909d3d)
